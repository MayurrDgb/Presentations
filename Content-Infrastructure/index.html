STARTING POINT
The wall we
keep hitting
The Nov-2025 audit wasn't a content problem first. It was a system problem — we can't reliably ship to our own site.
01
Recommend-only agency. No CMS access → every change routes through group IT, with long, unpredictable delays.
02
Broken sitemap. Google can't crawl properly — ~343 of ~1,400 URLs seen, ~227 indexed.
03
Local pages invisible. The franchise network — our core asset — isn't indexed.
04
Zero structured data & slow pages. No schema.org; LCP >15s; images not in WebP/AVIF.
73.5%
no traffic from 73.5% of indexable pages. Almost all clicks come from our own brand name.
The fix isn't "write more". It's an architecture we can actually operate.

THE WRITE-BACK LOOP
Franchisee content edits (photos, text, hours) → written back to the Centre Data Layer → the page re-renders. Franchisees never touch Git; corporate never hand-edits local pages. Each side owns its own plane.
Result: structured data & an indexable local footprint are produced automatically — exactly the two things the audit found missing. (Google Business listings are driven by the franchisee CRM on its own track — outside this architecture.)

THE SHELL
An empty shell
that builds itself
A headless / hybrid framework that handles both planes at once:
▸
Next.js (App Router) on Vercel — or Astro. Static build for editorial, ISR / on-demand regeneration for the thousands of local pages.
▸
Auto multi-sitemap at build/revalidate — FR / EN / services / centres / blog. The broken-sitemap blocker disappears structurally.
▸
Schema.org generated from data — Organization, LocalBusiness, Breadcrumb, Service, FAQ, Article. Never hand-written.
▸
Built-in image pipeline — AVIF/WebP, fixed dimensions, lazy-load. Targets mobile LCP < 2.5s.
▸
Preview deploy per PR — the exact workflow Claude Code needs to ship safely.
THE TRADE
Group IT owns the rails — the platform, the CRM ↔ Data Layer integration, the back-office app.
They no longer gate every word. We push content; they keep the engine running.
